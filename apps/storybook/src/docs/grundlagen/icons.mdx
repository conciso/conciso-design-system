# Icons

Zwei Quellen, SVG inline, Farbgebung über `currentColor`: Die generischen UI-Icons (Pfeile,
Hinweise, Schließen, Feature-Symbole) kommen aus [Lucide](https://lucide.dev) (ISC-Lizenz),
das Paket `@conciso/design-system/icons` enthält nur noch die DS-eigenen Glyphen, für die es
kein Lucide-Pendant gibt. Die Entscheidung steht in ADR-0016.

Die DS-eigenen Glyphen sind die fünf Bereichs-Glyphen (Corporate ×2, Angewandte KI, Effektive
Software, Wirksame Organisationen, durchgehend Solid mit gefüllten Multi-Path-Symbolen) und
die drei UI-Glyphen `ui-caret-down`, `ui-check` und `ui-quote`. Quelle der Wahrheit sind
`icons/source/*.svg`; der Build erzeugt daraus `dist/icons/icons.json` und die weiteren
Paketexporte. Jeder Schlüssel liegt in der Registry als genau eine Variante vor, die Größe wird
über `width`/`height` oder CSS gesetzt, die `viewBox` bleibt dabei erhalten. Welche Glyphen die
Registry enthält: siehe Galerie unten.

## UI-Icons aus Lucide

Lucide zeichnet im Outline-Stil auf einem 24-px-Raster mit runden Enden. Lucide-Icons werden
nie ins DS-Paket kopiert, sondern direkt aus dem Lucide-Paket bezogen.

**CSS und HTML (`lucide-static`).** `npm install lucide-static`, dann die gewünschte SVG-Datei
aus `lucide-static/icons/<name>.svg` inline einbetten (kein `<img>`, damit die Farbe über CSS
steuerbar bleibt). Die Datei bringt `fill="none"`, `stroke="currentColor"`, runde Enden und
Ecken sowie `stroke-width="2"` mit. Die Strichstärke wird auf den DS-Token der Größe gesetzt,
sonst wirkt das Icon neben der DS-Typografie zu schwer:

```html
<svg width="24" height="24" viewBox="0 0 24 24" fill="none" stroke="currentColor"
     stroke-width="1.5" stroke-linecap="round" stroke-linejoin="round" aria-hidden="true">
  <path d="m6 9 6 6 6-6"/>
</svg>
```

```css
.mein-icon { stroke-width: var(--icon-stroke-md); }
```

Ein CSS-`stroke-width` schlägt das gleichnamige Attribut. Die Tokens `--icon-stroke-micro` bis
`--icon-stroke-xl` stehen im Abschnitt „Größen & Stroke-Width“. Für Chrome-Icons (Navigation,
Select, Combobox, Theme-Switch) gilt 1,5 (`--icon-stroke-md`).

**Angular (`@lucide/angular`).** `npm install @lucide/angular` (Peer Angular ≥ 17). Jedes Icon
ist eine eigene Standalone-Komponente mit Attributselektor am `<svg>`, nur importierte Icons
landen im Bundle:

```ts
import { LucideChevronDown } from '@lucide/angular';

@Component({
  imports: [LucideChevronDown],
  template: `<svg lucideChevronDown [size]="24" [strokeWidth]="1.5" aria-hidden="true"></svg>`,
})
export class Beispiel {}
```

`@lucide/angular` schreibt `strokeWidth` als Attribut, das Default ist 2, deshalb den Wert
explizit setzen. Die DS-Komponenten registrieren ihre Icons zentral in `cds-icons.ts`.

## Migration von den bisherigen `ui-*`-Icons

Bis auf `ui-caret-down`, `ui-check` und `ui-quote` sind alle `ui-*`-Schlüssel aus
`@conciso/design-system/icons` und `icons.json` entfallen. Wer einen davon importiert hat,
nimmt das Lucide-Icon mit dem Namen aus der Tabelle (Angular: PascalCase mit Präfix, also
`chevron-down` → `LucideChevronDown`).

Heroicons-Pfade. Bei Icons mit festem Platz (Buttons, Felder) das Ergebnis prüfen.

## Größen & Stroke-Width

Für Outline-Icons (Lucide und DS-Glyphen) skaliert die Stroke-Width mit der Icon-Größe, damit die visuelle
Gewichtung konsistent bleibt: Micro-Icons brauchen feine Linien, XLarge-Icons vertragen
kräftigere Konturen. Die Werte stehen als CSS Custom Properties (`--icon-stroke-micro` bis
`--icon-stroke-xl`) in `css/tokens.css`.

| Größe | Bezeichnung | Stroke-Width | Verwendung |
|---|---|---|---|
| 16 × 16 | Micro | 1 px | Inline-Icons in Text, Tabellenzeilen, kleine UI-Elemente |
| 24 × 24 | Small | 1,25 px | Standard-UI, Navigation, Buttons, Formulare |
| 32 × 32 | Medium | 1,5 px | Karten, Listen, Sidebar-Einträge |
| 48 × 48 | Large | 2 px | Feature-Bereiche, Onboarding, Erklär-Abschnitte |
| 64 × 64 | XLarge | 2,5 px | Leere Zustände, Illustrationen, Hero-Bereiche |

## Die vier Bereichs-Glyph-Familien (DS-eigen)

Jede Bereichs-Glyphe ist ein SVG mit `fill="currentColor"`, die Farbe ist nicht
eingebrannt, sondern wird vom Consumer über die CSS-Eigenschaft `color` auf dem
Wrapper-Element gesetzt.

| Bereich | Hintergrund | `color` |
|---|---|---|
| Corporate | `--co-50` (#E0F7F7) | `--tx-brand` (#333E48) |
| Angewandte KI | `--ki-50` (#F4FCD5) | `--ki-800` (#475705) |
| Effektive Software | `--es-50` (#EAF0FB) | `--es-700` (#1B3D9A) |
| Wirksame Organisationen | `--wo-50` (#EBF5E6) | `--wo-800` (#183A0E) |

Sonderfall Logo-Zeichen: Das C-Zeichen ist die Bereichsmarke von Corporate und
ausschließlich in Kombination mit dem Conciso-Logo zu verwenden. Für reguläre
Bereichs-Icons im Thema Unternehmen gilt wie bei den anderen Bereichen: Hintergrundfarbe
`--co-50`, `color: var(--co-800)`.

## Galerie

export const AREA_COLOR = {
  co: 'var(--tx-brand)',
  ki: 'var(--ki-800)',
  es: 'var(--es-700)',
  wo: 'var(--wo-800)',
};

export const AREA_BG = {
  co: 'var(--co-50)',
  ki: 'var(--ki-50)',
  es: 'var(--es-50)',
  wo: 'var(--wo-50)',
};

export const areaIcons = Object.entries(icons).filter(([, icon]) => icon.area !== 'ui');
export const uiIcons = Object.entries(icons).filter(([, icon]) => icon.area === 'ui');

export const IconTile = ({ iconKey, icon, background, color, border }) => {
  const [vbWidth, vbHeight] = icon.viewBox.split(' ').slice(2).map(Number);
  const svgAttrs =
    icon.style === 'solid'
      ? { fill: 'currentColor' }
      : { fill: 'none', stroke: 'currentColor', strokeWidth: icon.strokeWidth || '1' };
  return (
    <div style={{ display: 'flex', flexDirection: 'column', alignItems: 'center', gap: 'var(--s2)' }}>
      <div
        className="icon-size-swatch"
        data-area={icon.area}
        title={icon.name}
        style={{
          background,
          color,
          border,
          borderRadius: 'var(--r-md)',
          width: 56,
          height: 56,
          display: 'flex',
          alignItems: 'center',
          justifyContent: 'center',
        }}
      >
        <svg
          viewBox={icon.viewBox}
          width={vbWidth}
          height={vbHeight}
          aria-hidden="true"
          {...svgAttrs}
          dangerouslySetInnerHTML={{ __html: icon.body }}
        />
      </div>
      <span className="lbl">{iconKey}</span>
    </div>
  );
};

Alle DS-eigenen Glyphen aus der Registry (`@conciso/design-system/icons.json`), live gerendert.
Lucide-Icons stehen hier nicht, sie gehören nicht ins Paket (siehe oben, Galerie unter
[lucide.dev/icons](https://lucide.dev/icons)). Unter jeder Kachel steht der Schlüssel, den ein
Entwickler tatsächlich importiert; der Name aus der Registry liegt als Tooltip (`title`-Attribut)
auf der Kachel.

### Bereichs-Glyphen

Die fünf Bereichs-Glyphen, je in ihrer Bereichsfarbe (Hintergrund `--XX-50`, `color` aus
der Tabelle oben; `currentColor` im SVG übernimmt diese Farbe).

Die bereichsneutralen DS-eigenen UI-Glyphen auf neutraler Fläche, Farbe `--tx-primary`. Sie
bleiben im Paket, weil Lucide dafür kein gleichwertiges Icon hat: `ui-caret-down` (kräftiger
Caret auf 10er-`viewBox` für Nav-Toggles), `ui-check` (kleiner Haken auf 12er-`viewBox`) und
`ui-quote` (gefülltes Zitatzeichen).

## Verwendungsregeln

**Technische Regeln**

| Eigenschaft | Regel |
|---|---|
| Quelle | [lucide.dev](https://lucide.dev) (ISC). Keine eigenen Icons zeichnen, ausgenommen die DS-Glyphen ohne Lucide-Pendant. |
| Format | SVG inline, kein `<img>`, damit Farbe über CSS steuerbar bleibt |
| Größen | Ausschließlich 16, 24, 32, 48, 64 px, keine Zwischenwerte |
| Stroke-Width | Outline-Icons: 1, 1,25, 1,5, 2, 2,5 px, passend zur Größe; nie den Lucide-Default 2 stehen lassen, wenn die Größe etwas anderes vorsieht |
| Hintergrund-Rect | Im Code entfernen, Hintergrundfarbe kommt vom Parent-Element |
| Barrierefreiheit | Dekorativ: `aria-hidden="true"`, bedeutungstragend: `role="img"` + `aria-label` |
| viewBox | Bleibt bei jeder Darstellungsgröße unverändert (ein Wert pro Glyph in der Registry); Größe über `width`/`height` oder CSS setzen |

## Wie ein Icon entsteht (CONTRIBUTING § 10 Schritt 3)

Gilt nur für DS-eigene Glyphen. Bevor ein neues Icon entsteht, prüfen, ob Lucide es hat
(lucide.dev/icons): Dann kein Eintrag in `icons/source`, sondern Lucide nutzen.

1. Normalisiertes SVG unter `icons/source/{area|ui}-{name}.svg` ablegen. Farben als
   `currentColor`, Outline-Icons mit inline `stroke-width`, `width`/`height` weglassen (die
   Größe setzt der Consumer). Key-Präfix `co|ki|es|wo` für Bereichs-Glyphen, `ui` nur für DS-eigene UI-Glyphen.
2. `npm run build:icons` ausführen. Das Skript generiert `dist/icons/icons.json`,
   `dist/icons/icons.js`, `dist/icons/icons.d.ts` und `dist/icons/README.md` aus
   `icons/source/`.
3. Label und Verwendung optional in `icons/manifest.json` pflegen.

Quelle ist ausschließlich `icons/source/*.svg`, die generierten Dateien unter
`dist/icons/` werden nie von Hand editiert oder committet.

## DS-Glyphen

DS-Glyphen sind die Design-System-eigenen Icons: die Bereichs-Glyphen `co-*`, `ki-*`, `es-*`,
`wo-*` sowie `ui-caret-down`, `ui-check` und `ui-quote`. Sie stammen aus
`@conciso/design-system/icons` (generiertes `dist/icons/icons.js`), alle übrigen UI-Icons aus
Lucide. Die zentrale Icon-Registry `icons/cds-icons.ts` in der Angular-Lib ist die einzige
Import-Fläche für Komponenten-Icons: Komponenten importieren nie direkt aus `@lucide/angular`.
Ein Lucide-Icon wird nur dort registriert, wo das Design System kein eigenes Glyph definiert;
bekommt es später ein DS-Pendant, wird ausschließlich `cds-icons.ts` umgestellt.

## Dos & Don'ts

**Tun**

- Größe über `width`/`height` oder CSS setzen, die `viewBox` bleibt dabei unverändert
- Das Hintergrund-`<rect>` vor dem Einbinden entfernen, es dient nur der Designvorschau
- Bereichsfarbe für Hintergrund und Pfad einhalten, Konsistenz über alle Brand Areas
- Dekorative Icons mit `aria-hidden="true"` ausblenden, Screenreader überspringen sie
- Lucide-Icons mit der Strichstärke aus den `--icon-stroke-*`-Tokens zeichnen, nicht mit dem Default 2

**Nicht tun**

- Icons zwischen Bereichen tauschen, jedes Icon gehört zu genau einer Brand Area
- Nicht-standardisierte Größen verwenden (zum Beispiel 20 px, 36 px), bricht den visuellen
  Rhythmus
- Icons als `<img src>` einbinden, verhindert Farbanpassung und Dark-Mode-Unterstützung
- Das Hintergrund-Rect im Code belassen, erzeugt ungewollte farbige Fläche im Layout
- Lucide-SVGs ins DS-Paket oder in `icons/source` kopieren, sie kommen aus `lucide-static` bzw. `@lucide/angular`
