Dos & Don'ts
✓ Tun
  • ✓Bereichsfarbe -700 für farbigen Text — die einzige Stufe, die WCAG AA auf Weiß erfüllt
  • ✓Stufe -50 für Hintergründe und Tonal Overlays — sie wirkt, ohne zu dominieren
  • ✓Semantische Tokens --c-success, --c-warning, --c-error konsequent für Status einsetzen
  • ✓Jede Seite gehört zu genau einer Brand Area — deren Farbpalette durchgängig verwenden
  • ✓Neutrals (--tx-primary, --tx-secondary) für Fließtext — Bereichsfarben nur für Akzente
✕ Nicht tun
  • ✕Stufe -500 als Textfarbe auf Weiß — Corporate und Angewandte KI unterschreiten den AA-Schwellenwert
  • ✕Paletten verschiedener Bereiche auf derselben Seite mischen — bricht die Markenzugehörigkeit
  • ✕Bereichsfarbe für Fließtext — lange Texte in Farbe ermüden und verringern die Lesbarkeit
  • ✕Semantische Farben zweckfremden — --c-success nicht für dekorative grüne Elemente
  • ✕Hardcodierte Hex-Werte statt Tokens — verhindert Dark-Mode-Unterstützung und Theme-Wechsel

Tonal Elevation

Zusätzlich zur Shadow-Elevation wird eine semitransparente Schicht der Primärfarbe auf Oberflächen gelegt. Je höher das Level, desto stärker die Tönung – Tiefe durch Farbe statt nur Schatten.

Verwendung

Ebenen-Übersicht
0 --e0 Seiten-Hintergrund · Tabellen · Outlined Cards 1 --e1 Standard-Cards · Floating Action Button · Listen-Karten 2 --e2 Chip-Hover · Dropdown-Anker · interaktiver Hover-State 3 --e3 Navigation Drawer · Side Sheet · persistente Panels 4 --e4 Modal · Bottom Sheet · Dialoge mit Scrim 5 --e5 Tooltip · Snackbar · Autocomplete-Dropdown
Kombinationsregel

Level 1–2 können Schatten oder Tonal Overlay einsetzen. Level 3–5 kombinieren beide — der Schatten signalisiert Abstand zur Seite, die Tönung verstärkt die visuelle Zugehörigkeit zur Primärfarbe.

Dos & Don'ts
✓ Tun
  • ✓Level steigt mit z-Index: je weiter vorn ein Element liegt, desto höher sein Elevation-Level
  • ✓Level 1 für Standard-Cards und Listen-Elemente im normalen Seitenkontext
  • ✓Level 3–5 nur für Elemente die anderen Inhalt überlagern: Drawer, Modal, Tooltip
  • ✓Tonal Overlay ab Level 3 zusätzlich zum Schatten — verstärkt die Zugehörigkeit zur Primärfarbe
  • ✓Level 0 (kein Schatten) für Outlined-Varianten im Tabellen- oder Listen-Kontext
✕ Nicht tun
  • ✕Schatten als Dekoration ohne semantischen Grund — Elevation kommuniziert immer räumliche Hierarchie
  • ✕Mehrere Level-5-Elemente gleichzeitig sichtbar — zu viel visuelle Konkurrenz auf einer Ebene
  • ✕Level überspringen (z.B. direkt von 0 auf 4) — verwirrt die wahrgenommene räumliche Hierarchie
  • ✕Eigene box-shadow-Werte statt Tokens — bricht die Konsistenz im Dark Mode
  • ✕Tonal Overlay ohne zugehörigen Schatten auf Level 3–5 — die Kombination beider ist die Regel

ARIA Patterns

Focus-Ring

Sichtbarer Fokusindikator für alle interaktiven Elemente (WCAG 2.4.7).

--focus-ring: 0 0 0 3px var(--co-50), 0 0 0 5px var(--co-500); :focus-visible { outline: none; box-shadow: var(--focus-ring); }

Formulare & Fehler

Fehlermeldungen programmatisch mit dem Feld verknüpfen (WCAG 1.3.1, 3.3.1).

<input aria-invalid="true" aria-describedby="err-id"> <span id="err-id" role="alert"> Pflichtfeld </span>

Dekorative Icons

SVGs ohne inhaltliche Bedeutung vor Screenreadern verbergen (WCAG 1.1.1).

<svg aria-hidden="true" focusable="false" viewBox="0 0 24 24"> <path d="…"/> </svg>

Icon-only Buttons

Buttons ohne sichtbares Label brauchen ein zugängliches Textalternativ (WCAG 1.1.1).

<button aria-label="Menü öffnen"> <svg aria-hidden="true" focusable="false">…</svg> </button>

Tab Panels

Tabs als Tablist mit vollständigen ARIA-Relationen (WCAG 4.1.2).

<div role="tablist"> <button role="tab" aria-selected="true" aria-controls="panel-1" id="tab-1">Tab 1</button> </div> <div role="tabpanel" id="panel-1" aria-labelledby="tab-1" tabindex="0">…</div>

Live Regions

Dynamische Inhalte für Screenreader ankündigen (WCAG 4.1.3).

/* Status (höflich, unterbricht nicht) */ <div role="status" aria-live="polite"> Gespeichert. </div> /* Alert (sofort, unterbricht) */ <div role="alert" aria-live="assertive"> Verbindungsfehler. </div>

Touch Targets & Interaktionsflächen

Interaktive Elemente müssen mindestens 44 × 44 CSS-Pixel groß sein (WCAG 2.5.5 Level AAA / 2.5.8 Level AA in WCAG 2.2).

✓
Buttons & Links: min. 44 × 44px via Padding erreichen, auch wenn der sichtbare Bereich kleiner ist.
✓
Icon-Buttons: min. 48px empfohlen, sichtbares Icon kann kleiner sein.
✗
Kleine Chips/Badges: Nicht klickbar machen ohne ausreichende Trefferfläche. Padding erhöhen oder Wrapper verwenden.

Mindestgröße per CSS

.btn { min-height: 44px; min-width: 44px; padding: 10px 20px; } /* Icon-only: Fläche über padding */ .icon-btn { width: 48px; height: 48px; display: flex; align-items: center; justify-content: center; }

Reduzierte Bewegung & High Contrast

prefers-reduced-motion

Nutzer mit Gleichgewichts- oder Aufmerksamkeitsstörungen können Animationen deaktivieren (WCAG 2.3.3 AAA).

@media (prefers-reduced-motion: reduce) { *, *::before, *::after { animation-duration: 0.01ms !important; transition-duration: 0.01ms !important; scroll-behavior: auto !important; } }

forced-colors (High Contrast)

Windows High Contrast Mode ersetzt Farben durch Systemfarben. Grenzen durch Borders statt nur Farbe ausdrücken.

@media (forced-colors: active) { .btn-filled { /* Border sichert Sichtbarkeit */ border: 2px solid ButtonText; forced-color-adjust: none; } .btn-outlined { border-color: ButtonText; } }

prefers-color-scheme

Dark Mode folgt der Betriebssystem-Präferenz. Alle Farb-Tokens werden über [data-theme="dark"] überschrieben.

@media (prefers-color-scheme: dark) { /* Automatisch anwenden: */ :root { color-scheme: dark; } } /* Oder manuell per JS: */ document.documentElement .dataset.theme = 'dark';
